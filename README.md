# BMW PT-CAN Shiftlight

Модульный shiftlight для BMW: пассивно читает PT-CAN, определяет состояние
двигателя и обороты, затем управляет линейкой ярких RGB-сегментов перед
водителем.

## Архитектурная концепция

```text
BMW PT-CAN
    │  только чтение, без передачи кадров
    ▼
AtomS3R + Atomic CAN Base
    │
    ├─ приём и фильтрация CAN-кадров
    ├─ декодирование оборотов и статуса двигателя
    ├─ логика порогов переключения и аварийных состояний
    ├─ встроенный экран: RPM и текущая световая секция
    └─ UART Chain Bus, 115200 бод
             │
             ▼
       Grove cable, 2.0 м
             │
             ▼
Chain RGB #1 → #2 → #3
```

В проекте один контроллер. Он одновременно принимает BMW PT-CAN через нижний
Atomic CAN Base и ведёт цепочку индикаторов через штатный HY2.0-4P Grove-порт.
Отдельный контроллер для каждой матрицы не нужен.

### Поведение

- Контроллер работает на шине строго в режиме `listen-only`: shiftlight не
  должен передавать кадры в PT-CAN.
- На старте прошивка подтверждает, что CAN доступен, и обнаруживает все Chain
  RGB в цепочке.
- Логика shiftlight преобразует обороты в дискретные световые точки: зелёная
  зона, затем жёлтая, красная и redline-мигание.
- Встроенный экран AtomS3R показывает текущие обороты, номер активной точки
  и действующую привязку `RPM → точки`. Это диагностический экран при первом
  подключении и интерфейс для проверки калибровки без наблюдения за матрицами.
- Обновляются только изменившиеся LED-группы, а не весь экран на каждый
  CAN-кадр. Это сохраняет быстрый отклик на UART Chain Bus.
- При потере CAN-данных или связи с матрицами индикация гаснет; зависший
  предупреждающий сигнал недопустим.

### Настройка RPM и визуализации

Весь набор параметров собран в [`include/shiftlight_config.h`](include/shiftlight_config.h):

- `kShiftPoints` — пять RPM-точек переключения;
- `kDemoRpm` — одинаковый цикл 3000–7000 RPM для всех визуализаций;
- `kVisualizationType` — геометрия основной прошивки: центральные или нижние
  секции 4×4. Сейчас выбрана `kLowerBlocks`.

### Зафиксированная карта индикации

Три матрицы расположены слева направо. В каждой используется скруглённая
нижняя секция 4×4, координаты `x=2–5`, `y=4–7`; угловые пиксели темнее
основного цвета. Секции появляются справа налево.

| Точка | RPM | Индикация |
| ---: | ---: | --- |
| 1 | 4500 | Правая нижняя секция зелёная. |
| 2 | 5100 | Правая и центральная нижние секции зелёные. |
| 3 | 5700 | Правая и центральная нижние секции зелёные, левая жёлтая. |
| 4 | 6300 | Все три нижние секции красные. |
| 5 | 6500 | Нижняя полоса высотой 4 пикселя на всех матрицах мигает красным. |

В рабочем режиме экран показывает, например, `RPM 5100` и `POINT 2/5`.

### Сигнал RPM из PT-CAN

Основная прошивка использует следующий сигнал оборотов двигателя:

| Параметр | Значение |
| --- | --- |
| Шина | PT-CAN, 500 кбит/с, стандартные 11-битные ID |
| CAN ID | `0x0A5` |
| Данные | байт 5 — младший, байт 6 — старший |
| Тип | `uint16`, little-endian |
| Формула | `RPM = raw × 0.25` |
| Частота обновления | около 48 Гц |

Контроллер работает только на приём. При старте и при отсутствии новых кадров
RPM более 200 мс матрицы гасятся, а экран показывает единое жёлтое
диагностическое сообщение `WAITING FOR CAN`, разбитое на две крупные строки.
После получения RPM экран показывает обороты и текущую точку shiftlight:
зелёным до 5700 RPM, жёлтым от 5700 RPM и красным от 6300 RPM.

| 1 | M5Stack AtomS3R (ESP32-S3, встроенный 0.85" экран) | Единый контроллер: CAN-логика, fail-safe, Chain Bus master и экран диагностики/калибровки. |

## Сборка и прошивка

На Mac нужны Git и Python 3. M5Burner и Arduino IDE не нужны. Если Git
отсутствует, выполните `xcode-select --install`.

### Первый запуск

```bash
git clone https://github.com/untoco/shiftlight.git
cd shiftlight
python3 -m venv .tooling/platformio
.tooling/platformio/bin/python -m pip install --upgrade pip "platformio==6.1.19"
.tooling/platformio/bin/pio run
```

### Загрузка на AtomS3R

Подключите AtomS3R USB-C кабелем с передачей данных.

```bash
# Найти порт платы
.tooling/platformio/bin/pio device list

# Собрать и загрузить прошивку; укажите найденный порт
.tooling/platformio/bin/pio run --target upload --upload-port /dev/cu.usbmodem101
```

Имя порта может отличаться; берите его из `pio device list`. Повторная сборка
без загрузки: `.tooling/platformio/bin/pio run`.

Визуализации хранятся отдельно: [`Визуализация 01`](visualizations/visualization_01_three_matrix_redline),
[`Визуализация 02`](visualizations/visualization_02_three_matrix_blocks) и
[`Визуализация 03`](visualizations/visualization_03_lower_matrix_blocks). Сейчас по умолчанию
собирается основная прошивка из [`src/main.cpp`](src/main.cpp). Для запуска
визуализации в [`platformio.ini`](platformio.ini) временно меняется `src_dir`;
команды остаются теми же.

## Распределение интерфейсов AtomS3R

| Интерфейс | Линии AtomS3R | Подключение |
| --- | --- | --- |
| Atomic CAN Base | G5 / G6 | Нижний разъём Atom; CAN-контроллер ESP32-S3 + CA-IS3050G. |
| Chain RGB | Grove: G2 / G1 | Первая матрица через 2.0 м Grove-кабель, остальные `OUT → IN`. |

## Световая геометрия

Три матрицы дают полосу 24×8 пикселей размером примерно 72 мм без учёта
стыков. Используются три нижние секции 4×4 — по одной на матрицу.
