# BMW PT-CAN Shiftlight

Модульный shiftlight для BMW: пассивно читает PT-CAN, определяет состояние
двигателя и обороты, затем управляет линейкой ярких RGB-сегментов перед
водителем.

## Архитектурная концепция

```text
BMW PT-CAN
    │  только чтение, без передачи кадров
    ▼
AtomS3R + Atomic CAN Base
    │
    ├─ приём и фильтрация CAN-кадров
    ├─ декодирование оборотов и статуса двигателя
    ├─ логика порогов переключения и аварийных состояний
    ├─ встроенный экран: RPM и текущая световая секция
    └─ UART Chain Bus, 115200 бод
             │
             ▼
       Grove cable, 1.0 м
             │
             ▼
Chain RGB #1 → #2 → #3
```

В проекте один контроллер. Он одновременно принимает BMW PT-CAN через нижний
Atomic CAN Base и ведёт цепочку индикаторов через штатный HY2.0-4P Grove-порт.
Отдельный контроллер для каждой матрицы не нужен.

### Поведение

- Контроллер работает на шине строго в режиме `listen-only`: shiftlight не
  должен передавать кадры в PT-CAN.
- На старте прошивка подтверждает, что CAN доступен, и обнаруживает все Chain
  RGB в цепочке.
- Логика shiftlight преобразует обороты в дискретные световые точки: зелёная
  зона, затем жёлтая, красная и redline-мигание.
- Встроенный экран AtomS3R показывает текущие обороты, номер активной точки
  и действующую привязку `RPM → точки`. Это диагностический экран при первом
  подключении и интерфейс для проверки калибровки без наблюдения за матрицами.
- Обновляются только изменившиеся LED-группы, а не весь экран на каждый
  CAN-кадр. Это сохраняет быстрый отклик на UART Chain Bus.
- При потере CAN-данных или связи с матрицами индикация гаснет; зависший
  предупреждающий сигнал недопустим.

### Зафиксированная карта индикации

Три матрицы расположены слева направо. В каждой используется скруглённая
центральная секция 4×4, координаты `x=2–5`, `y=2–5`; угловые пиксели темнее
основного цвета. Секции появляются справа налево.

| Точка | RPM | Индикация |
| ---: | ---: | --- |
| 1 | 3800 | Правая центральная секция зелёная. |
| 2 | 4400 | Правая и центральная секции зелёные. |
| 3 | 5000 | Правая и центральная секции зелёные, левая жёлтая. |
| 4 | 5600 | Все три центральные секции красные. |
| 5 | 6200 | Все три матрицы мигают красным. |

В рабочем режиме экран показывает, например, `RPM 4400` и `POINT 2/5`.
Пороговая карта зафиксирована по Test 02; автомобильные CAN ID, масштаб RPM и
частота кадров всё ещё требуют пассивной проверки именно на PT-CAN автомобиля.

## Разработка и прошивка

Прошивка — стандартный Arduino C++ для ESP32-S3. Для сборки используется
PlatformIO Core в командной строке: отдельная IDE, M5Burner или иное
графическое приложение не нужны. Такой проект одинаково собирается на macOS,
Linux и Windows.

### Что нужно на чистой macOS

Нужны только `git` и Python 3. Их наличие можно проверить так:

```bash
git --version
python3 --version
```

Если `git` отсутствует, установите инструменты разработчика macOS командой
`xcode-select --install`. Если отсутствует Python 3, установите его через
Homebrew (`brew install python`) или с [python.org](https://www.python.org/downloads/macos/).
Среда разработки M5Stack, Arduino IDE и M5Burner не требуются.

### Первый запуск после клонирования

`.tooling` не хранится в Git: это локальная изолированная среда Python. Она
создаётся первой командой ниже и может быть в любой момент удалена и создана
снова. `.pio` — аналогично локальный каталог с результатами сборки.

```bash
git clone https://github.com/untoco/shiftlight.git
cd shiftlight

# Создать локальную среду только для этого репозитория
python3 -m venv .tooling/platformio

# Установить проверенную версию PlatformIO Core
.tooling/platformio/bin/python -m pip install --upgrade pip "platformio==6.1.19"

# Первая сборка также скачает ESP32-S3 toolchain, Arduino framework и M5-библиотеки
.tooling/platformio/bin/pio run
```

На Windows путь к программам окружения будет
`.tooling\platformio\Scripts\` вместо `.tooling/platformio/bin/`.

### Сборка, деплой и мониторинг

Подключите AtomS3R качественным USB-C кабелем с передачей данных. Atomic CAN
Base и Chain RGB могут быть подключены; автомобильную шину для тестовой
прошивки подключать не нужно.

```bash
# Собрать прошивку
.tooling/platformio/bin/pio run

# Найти имя подключённого USB-порта
.tooling/platformio/bin/pio device list

# Записать прошивку в AtomS3R
.tooling/platformio/bin/pio run --target upload --upload-port /dev/cu.usbmodem101

# Открыть диагностический вывод; выход — Ctrl+C
.tooling/platformio/bin/pio device monitor --port /dev/cu.usbmodem101 --baud 115200
```

`/dev/cu.usbmodem101` — пример имени порта на текущем Mac; оно может меняться
после переподключения кабеля: всегда используйте имя из `pio device list`.
Настройки платы, библиотек и специального режима загрузки AtomS3R
`--no-stub` хранятся в [`platformio.ini`](platformio.ini), поэтому параметры
загрузки вручную добавлять не нужно.

Сценарии тестов хранятся отдельно: [`Test 01`](tests/test_01_three_matrix_redline)
и [`Test 02`](tests/test_02_three_matrix_blocks). Сейчас `platformio.ini`
собирает и загружает Test 02 через `src_dir`. После обновления исходников из
Git достаточно повторить `pio run`, а затем команду загрузки.

## Распределение интерфейсов AtomS3R

| Интерфейс | Линии AtomS3R | Подключение |
| --- | --- | --- |
| Atomic CAN Base | G5 / G6 | Нижний разъём Atom; CAN-контроллер ESP32-S3 + CA-IS3050G. |
| Chain RGB | Grove: G2 / G1 | Первая матрица через 1.0 м Grove-кабель, остальные `OUT → IN`. |

## Световая геометрия

Три матрицы дают полосу 24×8 пикселей размером примерно 72 мм без учёта
стыков. Используются три центральные секции 4×4 — по одной на матрицу.

## Неподтверждённые пункты до подключения к автомобилю

1. Скорость и топология конкретного PT-CAN.
2. CAN ID и масштаб оборотов двигателя.
3. Наличие, ID и кодировка передачи; она не требуется для первой версии
   shiftlight.
4. Вибрационная и температурная пригодность финального корпуса и креплений.
