# BMW PT-CAN Shiftlight

Модульный shiftlight для BMW: пассивно читает PT-CAN, определяет состояние
двигателя и обороты, затем управляет линейкой ярких RGB-сегментов перед
водителем.

## Архитектурная концепция

```text
BMW PT-CAN
    │  только чтение, без передачи кадров
    ▼
AtomS3R + Atomic CAN Base
    │
    ├─ приём и фильтрация CAN-кадров
    ├─ декодирование оборотов и статуса двигателя
    ├─ логика порогов переключения и аварийных состояний
    ├─ встроенный экран: RPM и текущая световая секция
    └─ UART Chain Bus, 115200 бод
             │
             ▼
       Grove cable, 0.5 м
             │
             ▼
Chain RGB #1 → #2 → #3 → #4 → #5
```

В проекте один контроллер. Он одновременно принимает BMW PT-CAN через нижний
Atomic CAN Base и ведёт цепочку индикаторов через штатный HY2.0-4P Grove-порт.
Отдельный контроллер для каждой матрицы не нужен.

### Поведение

- Контроллер работает на шине строго в режиме `listen-only`: shiftlight не
  должен передавать кадры в PT-CAN.
- На старте прошивка подтверждает, что CAN доступен, и обнаруживает все Chain
  RGB в цепочке.
- Логика shiftlight преобразует обороты в дискретные световые секции: зелёная
  зона, затем жёлтая, красная и мигание перед переключением.
- Встроенный экран AtomS3R показывает текущие обороты, номер активной секции
  и действующую привязку `RPM → секции`. Это диагностический экран при первом
  подключении и интерфейс для проверки калибровки без наблюдения за матрицами.
- Обновляются только изменившиеся LED-группы, а не весь экран на каждый
  CAN-кадр. Это сохраняет быстрый отклик на UART Chain Bus.
- При потере CAN-данных или связи с матрицами индикация гаснет; зависший
  предупреждающий сигнал недопустим.

Пороговые обороты, CAN ID, кодировки и периодичность кадров пока **не
подтверждены**. Их определим по пассивному логу именно PT-CAN автомобиля; ранее
наблюдавшиеся K-CAN2 кадры к этой настройке не относятся.

### Черновая карта секций

Это только пример будущей калибровки. Он иллюстрирует правило: каждые 100 RPM
включают следующую логическую секцию. Значения не должны попасть в постоянную
прошивку до проверки на автомобиле.

| RPM | Включённые секции |
| ---: | --- |
| 3000 | 1 |
| 3100 | 1–2 |
| 3200 | 1–3 |
| … | … |

В рабочем режиме экран будет показывать, например, `RPM 3100` и `SECTION 2/80`.
Эти цифры должны совпадать с фактически подсвеченными группами из четырёх LED
на линейке.

## Модули первой версии

| Количество | Модуль | Назначение |
| ---: | --- | --- |
| 1 | M5Stack AtomS3R (ESP32-S3, встроенный 0.85" экран) | Единый контроллер: CAN-логика, fail-safe, Chain Bus master и экран диагностики/калибровки. |
| 1 | M5Stack Atomic CAN Base (CA-IS3050G) | Изолированный физический интерфейс с BMW PT-CAN. Подключается снизу AtomS3R. |
| 5 | M5Stack Chain RGB | Пять каскадных RGB-матриц 8×8; всего 320 LED. |
| 1 | M5Stack Unbuckled Grove Cable, 0.5 м | Съёмный кабель AtomS3R → первая Chain RGB. |
| 5 | Chain Bridge | Входит в комплекты Chain RGB и соединяет соседние секции. |

## Разработка и прошивка

Прошивка — стандартный Arduino C++ для ESP32-S3. Для сборки используется
PlatformIO Core в командной строке: отдельная IDE, M5Burner или иное
графическое приложение не нужны. Такой проект одинаково собирается на macOS,
Linux и Windows.

### Первичная настройка

В корне проекта создаётся изолированное окружение, поэтому PlatformIO и его
зависимости не меняют системный Python или настройки macOS:

```bash
cd /путь/к/shiftlight
python3 -m venv .tooling/platformio
.tooling/platformio/bin/python -m pip install platformio
```

При первой сборке PlatformIO сам загрузит компилятор ESP32-S3, Arduino
framework и библиотеки M5Stack. На Windows путь к программам окружения будет
`.tooling\platformio\Scripts\` вместо `.tooling/platformio/bin/`.

### Сборка и загрузка

```bash
# Собрать прошивку
.tooling/platformio/bin/pio run

# Найти имя подключённого USB-порта
.tooling/platformio/bin/pio device list

# Записать прошивку в AtomS3R
.tooling/platformio/bin/pio run --target upload --upload-port /dev/cu.usbmodem101

# Открыть диагностический вывод; выход — Ctrl+C
.tooling/platformio/bin/pio device monitor --port /dev/cu.usbmodem101 --baud 115200
```

`/dev/cu.usbmodem101` — пример имени порта на текущем Mac; оно может меняться
после переподключения кабеля. Настройки платы и зависимостей хранятся в
[`platformio.ini`](platformio.ini), а первый безопасный тест одной Chain RGB —
в [`src/main.cpp`](src/main.cpp) и [`TESTING.md`](TESTING.md).

## Распределение интерфейсов AtomS3R

| Интерфейс | Линии AtomS3R | Подключение |
| --- | --- | --- |
| Atomic CAN Base | G5 / G6 | Нижний разъём Atom; CAN-контроллер ESP32-S3 + CA-IS3050G. |
| Chain RGB | Grove: G2 / G1 | Первая матрица через 0.5 м Grove-кабель, остальные `OUT → IN`. |

## Световая геометрия

Пять матриц дают полосу 40×8 пикселей размером примерно 120 мм без учёта
стыков. Базовый вариант использует группу из четырёх LED как одну логическую
секцию: 80 потенциальных сегментов. Практическая калибровка может объединить их
в 20–40 более крупных ступеней для более читаемой шкалы.

## Неподтверждённые пункты до подключения к автомобилю

1. Скорость и топология конкретного PT-CAN.
2. CAN ID и масштаб оборотов двигателя.
3. Наличие, ID и кодировка передачи; она не требуется для первой версии
   shiftlight.
4. Целевые обороты, которые зависят от выбранной передачи, температуры и
   режима двигателя.
5. Вибрационная и температурная пригодность финального корпуса и креплений.
